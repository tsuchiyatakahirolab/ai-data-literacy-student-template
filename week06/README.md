# Week 06: AIと成果物を作る

> 講師の動画実演用サンプルです。受講者本人の課題提出ではありません。

## 成果物

### 新入生向け：授業でAIを使うときの案内

この授業では、生成AIを、説明を聞く、情報を整理する、文章の案を作るために使えます。AIの答えには誤りや根拠不足があるので、出力をそのまま提出せず、次の順に確認しましょう。

まず、AIの答えにある数字・日付・出典を、配布資料や元の資料で探します。同じ情報があるか、いつの資料かを確かめ、確認できなかった点も書き残してください。

次に、長い文を分け、読者が最初に何を開き、何を確かめるかが分かる言葉に直します。AIに判断を丸投げせず、最終的な内容は自分で確かめます。

最後に、自分のGitHubのweek06/README.mdに、成果物と、使ったAIの名前・任せた作業・自分で確認や修正をした点・未確認の点を短く記録します。保存した版のcommitページを開き、URLに「/commit/」があることを確認して、授業で案内された提出フォームへ送りましょう。

案内本文：375字（改行を除く）。

1枚資料を使う場合の例：[案内資料を開く](ai_use_notice.png)

## 制作意図

生成AIを少し使ったことがあり、出典確認とGitHub提出に慣れていない新入生が、最初の行動を選べる案内にする。

## 使用したAI

GitHub Copilot（文案の初稿）。Codex（初稿の修正、1枚資料の作成、条件・文字数の機械的照合）。

## 使用した機能

文章生成、文章の修正、図形と文字による1枚資料作成。画像生成機能は使っていない。

## AIに任せたこと

配布ブリーフの3条件を含む初稿をCopilotで作成し、Codexで具体的な行動が分かる案に修正した。

## 自分で確認・修正したこと

この欄は実演用の確認記録です。確認はAIエージェントが行っており、教員本人や第三者によるレビューを済ませたという意味ではありません。

- 配布ブリーフと照合し、「AIを使ってよい」「丸投げしない」「使用AIと確認点をGitHubに記録する」の3条件が残ることを点検した。
- Copilotの初稿は272字だったため、300〜500字の条件に合わせて375字へ修正した。
- 「出典や事実関係が正しいかを調べる」を、「数字・日付・出典を元資料で探す」「いつの資料か確かめる」という行動に具体化した。
- 大学名、締切、学内URL、担当者名を創作していない。1枚資料の文章も同じ案内を使用した。

## 残った問題

実際の新入生に読んでもらう確認は未実施。授業固有の締切・提出フォーム・教員へのアクセス権は、この一般例では確認していない。受講者は授業の指示を確認し、自分自身で提出する。
